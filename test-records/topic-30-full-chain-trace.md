## 二、发现的问题点（按影响排序）

### 1. 小林 Agent 绑定了慢速模型供应商（最大延迟问题）
小林的三次发言耗时 50.6s / 103.0s / 51.8s，全部在 50 秒以上；其他 agent 全部在 6–14s。日志证实小林的请求走的是另一个 apiKey（`sk-scjjoaifoftv...`，3 次调用），其余 agent 走 `sk-oYPw2WuR3OHfu8z...`（13 次调用）。**P90=51.8s 完全由小林贡献**。当天整体讨论节奏多次被小林的单次调用卡住一分钟以上。
建议：检查小林的模型配置（apiKey/baseUrl/modelName），与其他 agent 对齐，或对慢供应商加超时与降级。

### 2. 超时自动收束的结论质量失效
69 分钟、23 条消息的讨论，最终结论只有 14 字开场白「给大家总结一下本次讨论内容。」并直接广播给用户（TOPIC_CLOSED 事件）。收束 Agent（老王/deepseek-v4-flash）只输出了引言就停了，代码侧无长度/内容校验、无重试，直接判定"成功"。
建议：收束结果加最小长度或内容启发式校验，不达标重试一次或换 concluder。

### 3. 路由判定 LLM 耗时不稳定（3.0s / 3.5s / 15.7s）
第三条用户消息发出后 31.9s 才收到 agent 回复，其中 15.7s 花在路由判定。路由判定是每条用户消息的前置税，长尾直接拖慢首响应。
建议：路由判定换轻量模型/加超时（>5s 降级到规则判定），或对已 @提及 agent 的消息跳过路由判定直接进 DISCUSS。

### 4. 消息摘要功能大部分失效（5/7 为空）
msgId 537/539/540/541/546 的摘要 LLM 原始输出为空（`raw=`），仅 542/544 有正常输出。空输出与当天 34 条 StTemplateRenderer 渲染错误（`'true' came as a complete surprise to me`，全部来自 msg-summary 线程）时间线吻合——摘要模板渲染失败导致上游就输出了空内容。
建议：修复 message-summary 模板的 StringTemplate 语法问题（这也是 ERROR 日志的主体）。

### 5. 话题画像解析失败：模型输出 EOS token
topicId=30 的话题画像 LLM 输出为 `raw=<｜end▁of▁sentence｜>`（DeepSeek 系模型的结束符泄漏到内容里），JSON 解析失败被跳过。topicId=28 同样失败（raw 为空）。
建议：解析前对 `<｜end▁of▁sentence｜>` 之类的特殊 token 做清洗；连续失败时告警。

### 6. 16 次选中发言但只产出 9 条消息
RANK_SPEAKERS 选中了 16 次（另有 7 次选中后没有「Agent发言已入库广播」记录）。需要结合 DiscussNode 的 passedAgentIds/降级链逻辑确认这 7 次是正常的 PASS（如所有 agent 都 pass 后进入等待）还是异常漏发。

### 7. 主循环等待时长日志异常
首次推进后打印「此次需要等：9223372036854775秒」（Long.MAX_VALUE），后续轮次为 2 秒。要么是日志打印了未初始化的等待值，要么首轮确实无限等待——两种情况都值得核对 runLoop 的等待计算逻辑。
