## 二、发现并修复的缺陷

### 缺陷 1：`agent.api_key` 列长度不足，存不下长 JWT
- **现象**：给老王配置 CloudBase 的长 JWT（796 字符）时，`PUT /api/agents/1` 返回 `INTERNAL_ERROR`。后端日志：`Data truncation: Data too long for column 'api_key'`。
- **根因**：MySQL `agent.api_key` 定义为 `VARCHAR(255)`，而部分网关（CloudBase）用长 JWT 作为 apiKey。
- **修复**：
  - 数据库：`ALTER TABLE agent MODIFY COLUMN api_key VARCHAR(1024)`（脚本 `scripts/DbFixApiKey.java`，日志 `logs/09-db-fix-apikey.log`）。
  - 源码：同步修正 [schema.sql](../start/src/main/resources/schema.sql) 的 `api_key` 为 `VARCHAR(1024)`，避免重建表回退。

### 缺陷 2：Spring AI baseUrl 拼接双重版本号导致 404（核心缺陷）
- **现象**：两个 Agent 直连 curl 均正常（200），但经后端调用全部 `404 - 404 page not found`（`ALL_AGENTS_FAILED` / `TOPIC_CONCLUSION_FAILED`）。
- **根因**：`SpringAiLlmService.buildChatModel` 只设了 `baseUrl`，未设 `completionsPath`。Spring AI 默认在 baseUrl 后拼 `/v1/chat/completions`，导致：
  - StepFun：`.../step_plan/v1` + `/v1/chat/completions` → `.../step_plan/v1/v1/chat/completions` ❌
  - CloudBase：`.../v1/ai/cloudbase` + `/v1/chat/completions` → 路径错误 ❌
- **修复**：[SpringAiLlmService.java](../dingRing-infrastructure/src/main/java/com/dingring/infrastructure/llm/SpringAiLlmService.java) 新增 `resolveUrl()`，按 baseUrl 是否含路径智能拆分 `baseUrl` + `completionsPath`：
  - 无路径（如 `https://api.deepseek.com`）→ 保持默认 `/v1/chat/completions`；
  - 含路径 → 以该路径为版本化前缀拼 `/chat/completions`；
  - 已以 `/chat/completions` 结尾 → 原样使用。
- **回归**：新增单测 `SpringAiLlmServiceTest`（5 条，覆盖 DeepSeek/StepFun/CloudBase/全路径/尾斜杠），全部通过（`logs/10-unit-test-resolveurl.log`）。

## 四、端到端讨论实录（第 2 轮，真实 LLM）

**主题**：MySQL 索引失效的常见场景

1. 用户：「大家聊聊 MySQL 索引失效都有哪些常见场景？最好举个实际例子」
2. **老王（qwen3.5-plus）**：隐式类型转换——varchar 字段传数字（`WHERE phone = 13800000000` 不加引号），MySQL 逐行转换导致索引失效、全表扫描。
3. **老王（第 2 条，auto-replies=2 自动接话）**：对索引列做函数——`WHERE DATE(create_time) = '...'` 失效，应改 `BETWEEN` 范围查询。
4. 用户「@苏教授 请总结一下」→ 触发收束（`IN_PROGRESS → CONCLUDING`）。
5. **苏教授（step-3.7-flash）**：输出 STAR 结构化结论（Situation/Task/Action/Result + 逐人点评），主题关闭（`TOPIC_CLOSED`）。
6. 异步生成 **4 张知识卡片**（`CARD_GENERATED`）。

**WebSocket 协议帧全部符合预期**：`NEW_MESSAGE` / `AGENT_TYPING`(开关) / `TOPIC_STATUS_CHANGED` / `TOPIC_CLOSED` / `CARD_GENERATED`。

## 六、遗留观察项（非阻塞）

1. **auto-replies 行为提示**：用户不 @ 任何人时，后端按配置 `auto-replies=2` 让 Agent 连续接话 2 条，属预期设计。第 2 轮 UI 测试中「老王连发两条相似回复」即此机制；若希望闲聊场景更克制，可调低 `dingring.orchestrator.auto-replies`。
2. **StepFun `step_plan` 端点特性**：该模型 reasoning（思维链）占用大量 completion tokens，`content` 需要足够的 `maxTokens`（本次专家设 3072）才能完整返回，否则可能被截断为空。建议专家类 Agent maxTokens 不宜过小。
3. **侧栏重复群名**：存在两个同名「联调测试群-0727」(groupId=3、4)，为多次联调创建的测试数据，可按需清理。
4. **apiKey 明文存储**：`agent.api_key` 明文入库、无格式校验（仅非空），生产环境建议加密存储。
