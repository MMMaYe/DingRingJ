# 03 核心链路图 ⭐

本篇是 wiki 的核心，用时序图 / 流程图详解每条关键链路。所有节点均对应真实类与方法。

---

## 链路一：用户消息全链路（总览）

从用户在前端发一条消息，到 Agent 群展开讨论的完整旅程。

```mermaid
sequenceDiagram
    autonumber
    participant FE as 前端 Chat 页
    participant WS as ChatWebSocketHandler
    participant DP as WsMessageDispatcher
    participant CO as ChatOrchestrator
    participant DB as MessageRepository
    participant DE as DiscussionEngine
    participant EX as 群虚拟线程执行器

    FE->>WS: WS 发送 {type:SEND_MESSAGE, content}
    WS->>DP: handleTextMessage
    DP->>CO: onUserMessage(groupId, content, replyTo)
    CO->>CO: 查群(不存在→NOT_FOUND)<br/>查活跃主题取 topicId(无则 null)
    CO->>DB: save(GroupMessage USER)
    CO-->>FE: pushToGroup NEW_MESSAGE (广播全群)
    CO->>CO: parseMentions 解析 @提及
    CO->>CO: publish MessageSent 事件
    CO->>DE: onUserSignal(UserSignal)
    CO-->>DP: 同步返回 MessageDTO
    DE->>DE: 信号入队 + wake() CAS 防重入
    DE->>EX: 提交 runLoopSafely (群串行)
    Note over EX: 进入引擎主循环(异步)<br/>见链路二
```

**关键点**：
- `onUserMessage` 同步只做「落库 + 广播 + 投信号」，**意图路由与 Agent 发言全在引擎异步线程**完成。
- 消息落库后**立即**广播 `NEW_MESSAGE`，前端瞬时回显。
- 若群无活跃主题，`topicId=null`（消息暂不归属主题，但仍触发调度，后续建题时回填）。

## 链路二：引擎主循环 `runLoop`

引擎的心脏。每群一个单线程虚拟线程执行器，保证群内任务串行。

```mermaid
flowchart TD
    START([wake / onUserSignal 触发]) --> CAS{running CAS<br/>抢占成功?}
    CAS -->|否, 已在跑| END1([返回, 让位既有循环])
    CAS -->|是| LOOP[runLoop 开始]
    LOOP --> ACTIVE{查活跃<br/>IN_PROGRESS 主题?}

    ACTIVE -->|讨论态| POLL1["queue.poll(pace, 5~15s 随机)"]
    POLL1 --> SIG1{取到信号?}
    SIG1 -->|是| FOLD[fold 折叠连发消息]
    SIG1 -->|超时无信号| ADV[advanceDiscussion 自主推进]

    ACTIVE -->|闲聊态| POLL2["queue.poll() 不等待"]
    POLL2 --> SIG2{队列空?}
    SIG2 -->|是| EXIT([退出循环])
    SIG2 -->|否| FOLD

    FOLD --> HS[handleSignal 意图路由]
    HS --> CONCLUDED1{触发收束?}
    ADV --> CONCLUDED2{触发收束?}
    CONCLUDED1 -->|是, 返回 true| EXIT2([退出循环,<br/>让位结论任务])
    CONCLUDED2 -->|是| EXIT2
    CONCLUDED1 -->|否| LOOP
    CONCLUDED2 -->|否| LOOP

    EXIT --> FIN[finally: 复位 running]
    EXIT2 --> FIN
    FIN --> RECHK{队列非空?}
    RECHK -->|是| START
    RECHK -->|否| END2([结束])
```

**为什么收束后要退出循环**：结论生成任务 `generateConclusion` 也排在同一个群串行执行器上。若循环不退出，就会与结论任务**死锁**（同一单线程互等）。因此 `tryConclude` 触发后返回 `true`，让循环让位。

**线程模型**：
- 每群执行器：`Executors.newSingleThreadExecutor` + 虚拟线程工厂，线程名 `group-{id}-`。
- 画像提炼、卡片生成各自另起独立虚拟线程，不占用群执行器。
- `runLoopSafely` 的 `finally` 复位 `running` 后，若队列仍有信号则重新 `wake`（防丢唤醒）。

## 链路三：意图路由与追溯建题 `handleSignal`

```mermaid
flowchart TD
    HS[handleSignal] --> JUDGE[resolveJudge 选路由判定 Agent<br/>@提及者优先, 否则群首成员]
    JUDGE --> ROUTE["messageRouter.route()<br/>LLM 判定 Intent + Confidence + topicTitle"]
    ROUTE --> INTENT{Intent?}

    INTENT -->|CONCLUDE| C1{有活跃主题?}
    C1 -->|是| TC["tryConclude(USER)<br/>@提及者作总结者"]
    C1 -->|否| CHAT1[按闲聊 handleChat]

    INTENT -->|DISCUSS| D1{有活跃主题?}
    D1 -->|否| ENSURE[ensureTopic 追溯建题]
    D1 -->|是| NOOP[不动作<br/>消息已归属主题, 循环自然衔接]

    INTENT -->|CHAT| CH1[清零 lowDiscussStreak]
    CH1 --> CH2{有活跃主题?}
    CH2 -->|否| HANDLECHAT[handleChat 轻量应答]
    CH2 -->|是| NOOP2[讨论中闲聊插话不打断]

    ENSURE --> CONF{Confidence?}
    CONF -->|HIGH| CREATE[立即建题]
    CONF -->|LOW| STREAK{连续 LOW 达 2 次?}
    STREAK -->|是| CREATE
    STREAK -->|否| HANDLECHAT2[handleChat 轻量应答, 累计 streak]

    CREATE --> TITLE["标题=route.topicTitle()<br/>兜底截取用户消息前 20 字"]
    TITLE --> DUP{标题冲突?}
    DUP -->|DuplicateKey 并发| REUSE[沿用现有活跃主题]
    DUP -->|撞历史标题| SUFFIX["加·MMdd-HHmm 后缀重试一次"]
    DUP -->|无冲突| SAVE[保存 Topic]
    SAVE --> BACKFILL["backfillChatMessages<br/>回填上个主题关闭后最多 15 条闲聊"]
    BACKFILL --> PUB[publish TopicCreated + 推 WS TOPIC_CREATED]
```

## 链路四：讨论态推进 `advanceDiscussion`

超时无用户信号时，引擎自主驱动 Agent 发言。

```mermaid
flowchart TD
    ADV[advanceDiscussion] --> S1{terminator.reachedMaxRounds?<br/>Agent 发言数 ≥ 100}
    S1 -->|是| TC1["tryConclude(MAX_ROUNDS)"]
    S1 -->|否| S2{群/成员失效?}
    S2 -->|是| EXIT[退出]
    S2 -->|否| S3[被 @ 者从 passedAgents 移除, 恢复候选]
    S3 --> S4{候选 = 未 PASS Agent<br/>为空?}
    S4 -->|是| TC2["tryConclude(CONVERGED)"]
    S4 -->|否| S5{Moderator 启用 且 无 @?}
    S5 -->|是| MOD["moderatorService.decide()"]
    MOD --> MODC{wantsConclude?}
    MODC -->|是| TC3["tryConclude(MODERATOR)"]
    MODC -->|否| SPEAK[取指定发言者 + 引导语]
    S5 -->|否| SPEAK
    SPEAK --> SO[speakOnce 发言]
    SO --> RESULT{结果?}
    RESULT -->|SPOKE| CLR[清空 passedAgents]
    RESULT -->|PASSED| ADD[加入 passedAgents]
    ADD --> CONV{size ≥ converge-pass-count 2?}
    CONV -->|是| TC4["tryConclude(CONVERGED)"]
    CONV -->|否| CONT[继续循环]
    RESULT -->|CONCLUDED / FAILED| EXIT2[退出循环]
    CLR --> CONT
```

**收束触发来源 `triggeredBy` 全集**：`USER`（用户结束/CONCLUDE 意图）、`AGENT`（Agent 自报 `[[CONCLUDE]]`）、`MAX_ROUNDS`（熔断）、`CONVERGED`（连续 PASS 收敛）、`MODERATOR`（主持人判定）、`RECONCILE`（对账重放）。

## 链路五：一次 Agent 发言 `speakOnce`（含流式）

```mermaid
sequenceDiagram
    autonumber
    participant DE as DiscussionEngine
    participant SS as SpeakerScheduler
    participant CB as ContextBuilder
    participant LLM as LlmService
    participant DB as MessageRepository
    participant FE as 前端

    DE->>SS: rank(候选 Agent, ctx) 评分降序
    Note over SS: @提及=1000 / 引用+500 / 基础100<br/>-发言数×10 + random(0,20)
    SS-->>DE: 降级链 (首位优先, 失败接力次位)
    loop 对每个候选 Agent
        DE->>DE: publish AgentSelected
        DE-->>FE: pushToGroup AGENT_TYPING(true)
        DE->>CB: build(上下文) 组装 system+历史
        alt 流式开启 (streaming.enabled=true)
            DE->>LLM: chatStream(agent, prompt, msgs, onDelta)
            loop 每个 delta 块
                LLM-->>DE: onDelta(片段)
                DE->>DE: StreamMarkerGuard 过滤标记
                DE-->>FE: MESSAGE_DELTA {streamId, delta}
            end
        else 非流式
            DE->>LLM: chat(agent, prompt, msgs)
        end
        alt 内容含 [[PASS]] 或 讨论态空内容
            DE->>DE: 判 PASSED (不入库/不广播)
            DE-->>FE: MESSAGE_ABORT {streamId} (流式)
        else 内容含 [[CONCLUDE]]
            DE->>DB: stripMarkers 后入库 + 广播
            DE->>DE: tryConclude(AGENT, 该 Agent 为总结者)
        else 正常内容
            DE->>DB: stripMarkers 后 save
            DE-->>FE: MESSAGE_COMPLETE {streamId, message}(流式)<br/>或 NEW_MESSAGE(非流式)
            DE->>DE: publish MessageSent
        end
        DE-->>FE: AGENT_TYPING(false)
    end
    Note over DE: 全部候选失败 → 推 ERROR(ALL_AGENTS_FAILED)
```

**降级链哲学**：`chatWithRetry` 单 Agent 失败重试 1 次（流式重试换新 streamId）；仍失败则发布 `AgentFailed` 并接力评分次高的 Agent；全员失败才推 `ALL_AGENTS_FAILED`。

## 链路六：收束与结论生成

```mermaid
sequenceDiagram
    autonumber
    participant TR as 触发方(用户/Agent/熔断)
    participant CO as ChatOrchestrator
    participant TP as TopicRepository
    participant EX as 群串行执行器
    participant CB as ContextBuilder
    participant LLM as LlmService
    participant FE as 前端

    TR->>CO: conclude(topicId) 或 tryConclude
    CO->>CO: topic.startConcluding() IN_PROGRESS→CONCLUDING
    CO->>TP: update(乐观锁 version 匹配)
    alt 乐观锁失败(并发)
        TP-->>CO: false
        CO-->>FE: 抛 TOPIC_NOT_IN_PROGRESS
    else 成功
        CO-->>FE: TOPIC_STATUS_CHANGED (CONCLUDING)
        CO->>CO: publish TopicConcluding
        CO->>EX: 排队 generateConclusion(群串行)
        EX-->>FE: AGENT_TYPING(true)
        EX->>CB: buildForConclusion(STAR prompt + 全部消息 + 群记忆)
        EX->>LLM: chat (重试 1 次)
        alt 空结论
            LLM-->>EX: ""
            EX->>CO: rollbackConclusion CONCLUDING→IN_PROGRESS
            EX-->>FE: TOPIC_STATUS_CHANGED + ERROR(TOPIC_CONCLUSION_FAILED)
        else 有结论
            EX->>TP: topic.close() CONCLUDING→CLOSED<br/>concluderAgentId 写入 feature JSON
            EX->>EX: 落系统通知消息 SYSTEM_NOTICE
            EX-->>FE: TOPIC_CLOSED (conclusion, messageCount, closedAt)
            EX->>EX: publish TopicClosed 事件
        end
    end
```

**总结者选定**：用户 @提及 或 Agent 自身 `[[CONCLUDE]]` 指定的 Agent 优先；否则 `SpeakerScheduler` 评分最高的成员 Agent 兜底。**无「专家 Agent」概念**，任何成员均可总结。

## 链路七：知识卡片提取（事件驱动）

```mermaid
sequenceDiagram
    autonumber
    participant EX as 群执行器
    participant EP as SpringEventPublisher
    participant CEH as CardEventHandler
    participant VT as 独立虚拟线程 card-gen-{id}
    participant LLM as LlmService
    participant DB as CardRepository
    participant FE as 前端

    EX->>EP: publish TopicClosed
    EP->>CEH: @EventListener onTopicClosed (同步)
    CEH->>VT: 另起虚拟线程 generateCards (不阻塞群执行器)
    VT->>VT: 幂等检查(已有卡片跳过)<br/>总结 Agent 不存在跳过
    VT->>LLM: CARD_PROMPT 提取 Q&A JSON (最多重试 3 次)
    alt 成功
        VT->>VT: parseCards 容忍```json 包裹, 过滤缺字段
        VT->>DB: saveBatch
        VT->>EP: publish KnowledgeCardGenerated
        VT-->>FE: CARD_GENERATED {topicId, cardCount, cards}
    else 3 次全败
        VT->>VT: 仅记 ERROR 日志, 不阻塞
    end
```

**兜底对账**：`CardReconciler`（`@Scheduled` fixedDelay=10 分钟）扫近 7 天内 CLOSED、有结论但无卡片的主题，构造 `TopicClosed(triggeredBy=RECONCILE)` 重放 `generateCards` 幂等补生成。

## 链路八：画像与记忆注入

```mermaid
flowchart LR
    subgraph 提炼["用户画像提炼(两条路径, 均独立虚拟线程)"]
        P1["闲聊缓冲达 15 条<br/>DiscussionEngine.triggerProfileExtraction"]
        P2["TopicClosed 事件<br/>ProfileEventHandler(最多 30 条对话)"]
    end
    P1 --> PS["ProfileService.extractAndMerge<br/>(增量合并覆盖写回, 用户维度串行)"]
    P2 --> PS
    PS --> UP[(user_profile 表)]

    subgraph 注入["发言时上下文注入(ContextBuilder.buildSystemPrompt)"]
        A1[Agent 人设 systemPrompt]
        A2[群聊角色说明 花名]
        A3["memoryService.retrieveMemory(groupId)<br/>= 同群历史 Topic 结论(上限5)"]
        A4["profileService.getProfile<br/>= 跨群全局用户画像"]
    end
    UP -.读取.-> A4
    A1 --> PROMPT[最终 system prompt]
    A2 --> PROMPT
    A3 --> PROMPT
    A4 --> PROMPT
    PROMPT --> LLMCALL[LLM 发言调用]
```

> 结论生成上下文 `buildForConclusion` 注入**群记忆但不注入用户画像**。Agent 无独立记忆，记忆 = 群维度 Topic 结论 + 用户维度全局画像。

## 链路九：卡死主题自愈（Watchdog）

```mermaid
flowchart TD
    W["ConclusionWatchdog.rescueStuckTopics<br/>@Scheduled fixedDelay=60s"] --> Q["查 CONCLUDING 且 update_time<br/>早于 5 分钟的卡死主题"]
    Q --> ROLL[rollbackToInProgress]
    ROLL --> LOCK{乐观锁更新成功?}
    LOCK -->|冲突| SKIP[跳过]
    LOCK -->|成功| PUSH[推 TOPIC_STATUS_CHANGED]
    PUSH --> WAKE["discussionEngine.wake()<br/>重新推进讨论"]
```
