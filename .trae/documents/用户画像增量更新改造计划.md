# 用户画像增量更新 — 历史版本留存改造计划

## 一、概要

将用户画像从「覆盖写回」改为「版本化写回」，每次提炼后：
1. 将旧记录标记为失效（`status = 0`）
2. 插入一条新记录作为当前有效版本（`status = 1`）
3. 查询时只返回 `status = 1` 的记录

这样既保留了当前的画像读取行为，又保留了历史版本，后续可通过查询 `status = 0` 的记录追踪用户画像的成长轨迹。

---

## 二、当前状态分析

### 1. 表结构（当前）

```sql
user_profile (id, user_id, profile_text, feature, create_time, update_time)
```
- `user_id` 上有唯一约束（由 `ON DUPLICATE KEY UPDATE` 推断）
- 每次写回是覆盖更新，旧数据丢失

### 2. 调用链

```
TopicClosed 事件
  → ProfileEventHandler.extract()
    → SimpleProfileService.extractAndMerge()
      → UserProfileRepository.findByUserId()   // 查当前
      → UserProfileRepository.upsert()         // 覆盖写回
```

### 3. 涉及文件

| 文件 | 作用 |
|------|------|
| `dingRing-domain/.../domain/user/UserProfile.java` | 实体，含 id, userId, profileText, feature, createTime, updateTime |
| `dingRing-domain/.../domain/user/UserProfileRepository.java` | 仓储接口，含 findByUserId, upsert |
| `dingRing-domain/.../domain/service/ProfileService.java` | 服务接口，含 getProfile, extractAndMerge |
| `dingRing-infrastructure/.../mapper/UserProfileMapper.xml` | MyBatis XML，含 findByUserId, upsert（ON DUPLICATE KEY UPDATE） |
| `dingRing-infrastructure/.../mapper/UserProfileMapper.java` | Mapper 接口 |
| `dingRing-infrastructure/.../repository/UserProfileRepositoryImpl.java` | 仓储实现，设 createTime/updateTime 后调用 mapper |
| `dingRing-infrastructure/.../memory/SimpleProfileService.java` | 服务实现，extractAndMerge 中查旧 → LLM 提炼 → upsert 覆盖 |
| `dingRing-app/.../event/ProfileEventHandler.java` | 事件监听器 |

## 三、修改方案

### 3.1 数据库变更（需确认后执行）

**ALTER TABLE 语句：**
```sql
ALTER TABLE user_profile
    DROP INDEX /* 找出 user_id 上的唯一索引名 */,
    ADD COLUMN status TINYINT(1) NOT NULL DEFAULT 1 COMMENT '1=有效 0=失效',
    ADD INDEX idx_user_status (user_id, status);
```

> 注意：需要先查出 user_id 上的唯一索引名称（SHOW INDEX FROM user_profile），DROP 后改为普通索引。

### 3.2 UserProfile.java — 新增 status 字段

```java
/** 记录状态：1=有效, 0=失效 */
private Integer status;
```

同时新增常量供代码引用：

```java
public static final Integer STATUS_ACTIVE = 1;
public static final Integer STATUS_EXPIRED = 0;
```

### 3.3 UserProfileRepository.java — 接口变更

```java
public interface UserProfileRepository {
    /** 查询当前生效的画像（status = 1） */
    Optional<UserProfile> findByUserId(Long userId);

    /** 保存为新版本：将旧 status 置为 0，再插入 status=1 的新记录 */
    void saveNewVersion(UserProfile profile);
}
```

### 3.4 UserProfileMapper.xml — 改写 SQL

- `findByUserId`：加 `WHERE status = 1` 过滤
- 移除 `upsert`，新增：
  - `expireByUserId`：`UPDATE user_profile SET status = 0, update_time = NOW() WHERE user_id = #{userId} AND status = 1`
  - `insert`：`INSERT INTO user_profile (...) VALUES (...)`（不再使用 ON DUPLICATE KEY UPDATE）

### 3.5 UserProfileMapper.java — Mapper 接口变更

```java
UserProfile findByUserId(Long userId);
int expireByUserId(Long userId);
int insert(UserProfile profile);
```

### 3.6 UserProfileRepositoryImpl.java — 仓储实现变更

- `findByUserId`：不变，XML 层已加 status 过滤
- 移除 `upsert`，实现 `saveNewVersion`：
  ```java
  @Transactional
  public void saveNewVersion(UserProfile profile) {
      userProfileMapper.expireByUserId(profile.getUserId());
      LocalDateTime now = LocalDateTime.now();
      profile.setStatus(UserProfile.STATUS_ACTIVE);
      profile.setCreateTime(now);
      profile.setUpdateTime(now);
      userProfileMapper.insert(profile);
  }
  ```

### 3.7 SimpleProfileService.java — 调用变更

`extractAndMerge` 方法中：
- 将 `userProfileRepository.upsert(profile)` 改为 `userProfileRepository.saveNewVersion(profile)`
- 移除 `findByUserId` 中设置 id 的逻辑（因为新插入的记录不需要 id）

### 3.8 ProfileEventHandler.java — 不变

事件监听器无需改动，只要 `ProfileService.extractAndMerge()` 接口不变即可。

## 五、假设与决策

- **查询兼容**：`findByUserId` 只返回 `status = 1` 的记录，对上游调用方完全透明
- **事务安全**：`saveNewVersion` 中 expire + insert 在同一个事务中执行，防止并发下出现两个 `status=1` 或没有 `status=1` 的窗口
- **历史查询**：后续可通过 `UserProfileRepository` 新增 `findHistoryByUserId()` 方法查询历史版本，当前不实现
- **status 默认值**：表中已有数据自动被设为 `1`，无需迁移脚本

## 六、验证步骤

1. 启动应用，检查启动日志无异常
2. 发起一次群聊讨论，等待 TopicClosed 事件触发画像提炼
3. 检查数据库：
   - 旧记录 `status = 0`（失效）
   - 新记录 `status = 1`（有效）
4. 再次发起讨论，确认第二次提炼后：
   - 第一次的 `status=1` 变为 `status=0`
   - 新插入一条 `status=1` 的记录
5. 验证 `getProfile()` 接口返回最新的 `status=1` 的画像文本
